# anime-bot

Телеграм-бот, который отдаёт серии из канала-хранилища: поиск по названию,
выбор сезона → серии → озвучки, подписка за Telegram Stars, админка.

Описаний и обложек пока нет — задача этой версии только выдавать видео.

## Установка одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/zfd430792-coder/Vpn-/claude/traffic-consuming-bot-iuxyrf/install.sh | sudo bash
```

Спросит четыре вещи: токен бота от [@BotFather](https://t.me/BotFather), твой
Telegram ID (узнать у [@userinfobot](https://t.me/userinfobot)), `API_ID` и
`API_HASH` с [my.telegram.org](https://my.telegram.org) → API development tools.
Дальше сам поставит пакеты, заведёт venv, залогинит юзербота, **создаст
канал-хранилище и закрытую служебную группу**, выдаст боту права админа и
поднимет systemd-сервис.

**Вход юзербота — по QR-коду.** На российские номера коды по SMS часто не
доходят, поэтому по умолчанию предлагается QR: в терминале рисуется код, на
телефоне Telegram → Настройки → Устройства → Подключить устройство → навести
камеру. Код живёт минуту, обновляется сам, попыток пять. Вход по номеру
остаётся запасным вариантом.

Вопросы читаются из `/dev/tty`, так что `curl | bash` не ломается. Если не
хочется отвечать руками — передай переменными:

```bash
curl -fsSL <url>/install.sh | sudo BOT_TOKEN=... ADMINS=... API_ID=... API_HASH=... bash
```

## Как это работает

Хранилище — сам Telegram, у себя ничего не лежит. Заливаешь серию один раз,
дальше бот отдаёт её через `copy_message`: файл не перезаливается, трафик
сервера не тратится, **ограничения по размеру нет** — даже для файла на 4 ГБ.

```
   админ                канал-хранилище              юзер
     │                        │                       │
     │  видео + подпись       │                       │
     ├───────────────────────>│                       │
     │                        │   бот читает пост,    │
     │                        │   пишет в SQLite      │
     │                        │   (message_id)        │
     │                        │                       │
     │                        │   copy_message        │
     │                        ├──────────────────────>│
```

Зачем нужен юзербот, если есть бот:

| | Загрузить | Скачать |
|---|---|---|
| Bot API | 50 МБ | 20 МБ |
| Юзербот (аккаунт) | 2 ГБ | 4 ГБ |
| Юзербот + Premium | 4 ГБ | 4 ГБ |
| `copy_message` по готовому посту | **без лимита** | — |

То есть **юзербот заливает, бот отдаёт**. Юзербот же создаёт канал и служит
запасным путём выдачи, если у бота не вышло.

## Как добавлять серии

**Способ 1 — залить в канал-хранилище с подписью.** Бот там админ, увидит пост
сам. Понимает любой из форматов:

```
Тайтл Альфа
Сезон: 1
Серия: 7
Озвучка: Studio Band
```
```
Тайтл Альфа | 1 | 7 | AniLibria
Тайтл Альфа S01E07 [Studio Band]
Тайтл Альфа - 7 серия (AniLibria)
```

Качество дописывается туда же — строкой `Качество: 4к` или меткой в тексте:

```
Тайтл Альфа S01E07 [Studio Band] [4K]
Тайтл Альфа | 1 | 7 | AniLibria | 1080p
```

Поправил подпись — бот перечитает. Не разобрал — напишет админу, что именно не
понял.

**Способ 2 — прислать видео боту в личку.** С подписью — заведёт сразу; без
подписи — спросит название, сезон, серию, озвучку и качество по шагам. Бот сам скопирует
файл в канал.

**Способ 3 — файл уже на диске сервера:**

```
/pull /srv/video/alpha_s01e07.mkv | Тайтл Альфа | 1 | 7 | Studio Band
```

Заливает юзербот, поэтому проходят файлы до 2 ГБ (4 ГБ с Premium).

## Что видит пользователь

`/start` → меню: 🔍 Поиск · 📚 Каталог · 🔥 Популярное · 👤 Профиль · ⭐ Подписка.

Можно просто написать название — найдёт по совпадению, переживает опечатки
(нечёткое сравнение). Если совпадение одно, сразу открывает карточку.

Дальше **сезон → серия → озвучка → качество**. Лишние шаги пропускаются: один
сезон — сразу список серий, одна озвучка — сразу к качеству, одно качество —
сразу видео. В плеере: ⏮/⏭ по сериям (озвучка и качество сохраняются),
🎚 смена озвучки, 💎 смена качества, 📋 все серии.

## Качество

Поддерживаются два: **1080p и 4K**. 720 сознательно нет.

Качество берётся из подписи к файлу — понимаются `4K`, `4К` (русская буква),
`2160p`, `UHD`, а также `1080`, `1080p`, `FHD`. Метка может стоять где угодно:
отдельной строкой `Качество: 4к`, в скобках `[4K]`, просто в тексте. Если метки
нет, файл считается 1080p.

Кнопка качества показывается, только когда для этой серии в этой озвучке
действительно залито больше одного варианта — иначе бот не задаёт лишний
вопрос. Рядом с каждым качеством виден размер файла.

Один и тот же файл в разных качествах — это две записи, они не затирают друг
друга; повторная заливка того же качества обновляет ссылку.

## Поддержка

💬 в меню или `/support`. Человек пишет вопрос — и **на него заводится
отдельная тема** в служебной группе, названная его именем. Отвечать нужно
прямо в этой теме: бот передаст ответ человеку и пометит сообщение галочкой.
Вся переписка с одним человеком всегда в одном месте, перепутать нельзя.

- `/close` в теме — закрыть обращение (человеку сообщат, при новом вопросе
  откроется снова);
- `/reply <id> <текст>` в личке боту — ответить без тем, работает всегда;
- если тем нет или группа не настроена, обращения падают админам в личку.

Отвечать в теме могут только админы, сообщения остальных бот не передаёт.

## Подписка за звёзды

Четыре тарифа: неделя 50 ⭐, месяц 150 ⭐, 3 месяца 350 ⭐, навсегда 1000 ⭐.
Цены меняются в админке. Оплата — Telegram Stars (`XTR`), карт и провайдеров не
надо.

**Тестовая подписка** вместо бесплатных серий: человек включает её сам одной
кнопкой, даётся один раз, срок настраивается (по умолчанию 3 дня). Включается и
выключается из админки — выключил, и доступ остался только платным.

**Промокоды** двух видов: дающие подписку на N дней и дающие скидку в
процентах на следующую оплату. Создаются в админке по шагам — бот спросит тип,
величину, сам код (или придумает) и лимит использований. Скидка пересчитывает
цены в витрине и сгорает после оплаты.

Возврат звёзд: `/refund <ID>`.

## Предложения тайтлов

Люди пишут, что хотят увидеть, и голосуют. Сложность в том, что один и тот же
тайтл пишут по-разному: полным названием, одним словом, сокращением из первых
букв. Чтобы голоса не растекались:

- точное и уверенное совпадение засчитывается молча — сокращение из первых букв
  и отдельное слово из названия находят нужный тайтл;
- спорное бот не угадывает, а показывает похожие кнопками: «ты про это?»;
- подтверждённое написание запоминается псевдонимом, и в следующий раз то же
  сокращение попадает в цель без вопросов — система дообучается на ответах
  людей;
- в админке предложение можно закрыть, отклонить или слить с другим вручную,
  если автоматика всё же промахнулась.

## Служебная группа

`python -m anibot.setup` заводит закрытую супергруппу и включает в ней темы:

| Тема | Что туда идёт |
|---|---|
| 💡 Предложения | новые заявки на тайтлы |
| 💰 Платежи | оплаты, промокоды, включённые тесты |
| 📊 Статистика | сводки |
| 🛠 Логи и ошибки | старт, остановка, простой, ошибки уровня ERROR |
| 💬 по теме на человека | обращения в поддержку, заводятся сами |

Если Telegram темы не даст, всё уедет в общий чат группы; если и группы нет —
в личку админам. Ошибки схлопываются: одна и та же не чаще раза в пять минут.

## Когда сервис падает

Три разных механизма, потому что мёртвый сервер сам сообщение не отправит:

1. **Сервис упал, машина жива** — systemd дёргает `anime-bot-alert@`, тот шлёт
   в Telegram последние строки лога. Работает, даже когда бот не запускается.
2. **Бот поднялся** — при старте сообщает, сколько лежал. Считается по метке,
   которую бот обновляет раз в минуту, пока жив. Это же покрывает случай
   «сервер сам встал после перезагрузки».
3. **Умерла вся машина** — изнутри такое не отследить. Нужен внешний пинг:
   любой аптайм-монитор, дёргающий сервер раз в минуту.

## Админка

Кнопка ⚙️ в меню или `/admin`:

- 📊 статистика: тайтлы, серии, юзеры (и за сутки), подписки, баны, просмотры, заработок в звёздах
- 🎬 тайтлы: переименование, удаление вместе с сериями
- 📣 рассылка всем (с паузами, чтобы не влететь в лимиты)
- ⭐ выдать/снять подписку: `ID дни`
- 🚫 бан/разбан: `ID`, разбан `ID +`
- 💰 платежи и возвраты
- ⚙️ настройки: бесплатные серии, защита от пересылки, автоудаление выданного, цены тарифов

Команды: `/admin`, `/stats`, `/pull`, `/refund`.

## Настройки

`/etc/anime-bot/env` (права 600, внутри токены):

| Переменная | Что делает |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `ADMINS` | ID админов через запятую |
| `API_ID`, `API_HASH` | с my.telegram.org, для юзербота |
| `SESSION`, `STORAGE_CHANNEL` | заполняет `python -m anibot.setup` |
| `TRIAL_ENABLED` | включена ли тестовая подписка |
| `TRIAL_DAYS` | на сколько дней даётся тест |
| `SERVICE_GROUP`, `LOG_*` | служебная группа и её темы |
| `PROTECT_CONTENT` | запрет пересылки и сохранения выданного видео |
| `AUTODELETE` | удалять выданное видео через N минут (0 — не удалять) |
| `DELIVERY` | `bot` или `userbot` — кто отдаёт видео |

Настройки из таблицы (кроме токенов) после первого запуска живут в базе и
меняются из админки.

## Эксплуатация

```bash
journalctl -u anime-bot -f        # логи
systemctl restart anime-bot       # рестарт
python -m anibot.doctor           # проверить, что сломалось
journalctl -u anime-bot-alert@* # что уходило в тревогу
python -m anibot.setup            # перелогинить юзербота / создать канал заново
```

## Если что-то пошло не так

Первым делом — диагностика. Она проверяет токен, ID админа, данные и сессию
юзербота, канал-хранилище, права бота в нём и базу, и на каждую поломку пишет,
что именно чинить:

```bash
cd /opt/anime-bot && ENV_FILE=/etc/anime-bot/env .venv/bin/python -m anibot.doctor
```

**Перенастроить, не переустанавливая** (спросит токен и остальное заново,
сессию юзербота и канал сохранит):

```bash
cd /opt/anime-bot && sudo CONFIG_ONLY=1 bash install.sh
```

**Поправить руками** — всё лежит в `/etc/anime-bot/env`, после правки
`systemctl restart anime-bot`.

Про вставку токена: вставляй как есть, хоть вместе с текстом от @BotFather —
установщик сам выдернет токен, срежет невидимый мусор от терминала и переводы
строк из Windows-буфера, покажет, что принял, и сразу спросит Telegram, живой
ли токен. Не подошло — переспросит, а не упадёт.

## Тесты

```bash
bash tests/run.sh
```

Сеть подменена, токены не нужны. Покрыто: разбор подписей во всех форматах,
каталог и переходы, нечёткий поиск, квота и пейволл, счёт в звёздах и выдача
подписки после оплаты, админка и отказ обычному юзеру, бан, обе схемы заливки,
лимит 64 байта на `callback_data`, совпадение подписей всех 58 хендлеров с тем,
что прокидывает мидлварь, разбор ввода установщика (вставка с невидимым
мусором, токен вперемешку с текстом, `@имя` вместо ID), промокоды и скидки,
сопоставление предложений (аббревиатуры, опечатки, спорные случаи, обучение
на подтверждениях), выбор качества и пропуск лишних шагов, переписку с
поддержкой, а также миграцию старой базы под качество — данные должны
пережить пересборку таблицы.

## Что стоит знать

- **`file_id` привязан к боту.** Сменишь бота — старые ссылки не сработают.
  Поэтому в базе хранится `message_id` поста в канале, а не `file_id`: так
  каталог переживает смену бота, пока жив канал.
- **Не удаляй сообщения в канале-хранилище** — на них ссылается вся база.
- Бот должен остаться админом канала, иначе `copy_message` перестанет работать.
- Ответственность за то, что залито в канал, — на владельце бота.

## Структура

```
anibot/
  __main__.py      запуск бота
  setup.py         интерактивная настройка: логин юзербота + создание канала
  config.py        конфиг из окружения
  db.py            SQLite: каталог, юзеры, подписки, платежи
  parser.py        разбор подписей к видео
  search.py        нормализация названий и нечёткий поиск
  keyboards.py     инлайн-клавиатуры, фабрики callback-данных
  texts.py         все тексты сообщений
  service.py       проверка доступа и выдача серии
  userbot.py       Telethon: канал, заливка, запасная выдача
  middlewares.py   зависимости, регистрация юзера, баны
  handlers/        старт, каталог, плеер, подписка, админка, приём из канала
tests/             проверки без сети
install.sh         установка одной командой
```
