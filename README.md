# voice-bot

Телеграм-бот: пересылаешь ему голосовое, а он отвечает, с какого устройства
его записали: iPhone, Android, Telegram Desktop, macOS, Telegram X или
веб-версия.

## Как это работает

Голосовое в Telegram — это файл Ogg/Opus. В его заголовке (OpusTags)
кодировщик оставляет строку **Vendor** — имя своей сборки. У каждого клиента
Telegram сборка своя, поэтому по этой строке клиент и узнаётся. Это то же
поле, которое показывает `exiftool -a -G1 -u voice.ogg`, только exiftool боту
не нужен: заголовок разбирается прямо в Python.

| Vendor | Откуда голосовое |
|---|---|
| `libopus 1.5.1` | iPhone |
| `libopus unknown-fixed` | Android |
| `Lavf60.16.101` | Telegram Desktop |
| `libopus 1.3.1-fixed` | macOS (нативный клиент) |
| `libopus unknown` | Telegram X |
| `tweb` | Telegram Web K |
| `telegram-web-a` | Telegram Web A |

При пересылке Telegram отдаёт тот же самый файл без перекодирования, поэтому
работает и с чужими голосовыми: переслал — узнал.

## Что отвечает бот

- ✅ **iPhone** — строка точно есть в таблице.
- 🤔 **Похоже на Telegram Desktop** — точной строки нет, но узнаётся начало:
  `Lavf…` (это FFmpeg, через него пишет Desktop), `tweb…`, `telegram-web-a…`.
  Так бывает, когда клиент обновился и в строке сменился номер версии.
- 🤷 **Не знаю такой клиент** — строки нет в таблице, бот покажет её как есть.

Версии `libopus …` бот не угадывает: `libopus 1.5.2` может оказаться и
обновлённым iPhone, и чем-то другим, поэтому честнее сказать «не знаю».

Кроме голосовых, разбирает `.ogg` и `.opus`, присланные файлом. Работает
только в личке — в группах молчит.

## Чего бот не умеет

- **Модель телефона не определяет.** Строку Vendor оставляет кодировщик,
  вшитый в приложение Telegram, — она про приложение (iOS / Android / Desktop /
  веб), а не про железо. У всех айфонов она одна, у всех андроидов одна;
  Samsung от Xiaomi не отличить. Модели в файле нет ничем: Telegram вырезает
  метаданные.

## Кружки и видео

Трюк с Vendor держится на том, что в Ogg/Opus есть текстовое поле с именем
сборки. **Кружки — это MP4, такого поля там нет**, поэтому клиент по ним бот
не называет. Вместо этого он показывает всё, что реально лежит в файле и
может отличать клиентов:

- бренды `ftyp` (`isom`, `mp42`, …);
- кодеки дорожек (`avc1`, `mp4a`, …);
- имя кодировщика видео (`compressorname`, туда попадает сборка кодека);
- тег `©too` (кодировщик контейнера).

Это те же поля, что показывает `exiftool` на MP4, и на настоящем файле бот
даёт ровно то же. Пришли кружки с разных телефонов — сравни, отличается ли
что-то. Если по какому-то полю клиенты расходятся стабильно, его можно
занести в таблицу и называть клиент так же, как для голосовых. Пока это режим
разведки, а не готовый определитель.

## Установка одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/zfd430792-coder/Vpn-/claude/traffic-consuming-bot-iuxyrf/install.sh | sudo bash
```

Спросит только токен бота от [@BotFather](https://t.me/BotFather). Вставлять
можно прямо с текстом вокруг: установщик сам выдернет токен и сразу спросит у
Telegram, живой ли он. Дальше поставит пакеты, заведёт venv и поднимет
systemd-сервис `voice-bot`.

Без вопросов:

```bash
curl -fsSL <url>/install.sh | sudo BOT_TOKEN=123456:AAE... bash
```

Повторный запуск той же команды — это обновление: подтянет свежий код и
перезапустит сервис, а токен возьмёт из `/etc/voice-bot/env`.

## Запуск без установщика

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
BOT_TOKEN=123456:AAE... .venv/bin/python -m voicebot
```

На Windows задай токен через `set BOT_TOKEN=...` (cmd) или
`$env:BOT_TOKEN="..."` (PowerShell), потом запусти `python -m voicebot`.

## Нашёл новую строку

Каждую увиденную строку Vendor бот пишет в лог:

```bash
journalctl -u voice-bot -f
```

Новый клиент или версию допиши в `KNOWN` в `voicebot/clients.py` и
перезапусти сервис. Если у строки меняется только номер версии, а начало
узнаваемое, начало можно добавить в `FAMILIES`.

## Ограничения

- Узнаётся приложение, а не железо: на iPhone и iPad одно и то же приложение
  Telegram для iOS, а Desktop одинаков на Windows, Linux и macOS.
- Строки меняются с обновлениями клиентов: таблица — это снимок на сегодня.
- Кружочки (видеосообщения) не разбираются: это MP4, у них другой заголовок.
- Bot API отдаёт ботам файлы до 20 МБ. Голосовые столько не весят, но если
  прислать огромный `.ogg` файлом, бот так и скажет.

## Эксплуатация

```bash
journalctl -u voice-bot -f          # логи
systemctl restart voice-bot         # рестарт
systemctl disable --now voice-bot   # выключить
```

## Тесты

```bash
bash tests/run.sh
```

Сеть подменена, токен не нужен. Покрыто: чтение Vendor из настоящего файла
ffmpeg и из собранных вручную (на тех же файлах exiftool даёт то же самое),
заголовок, разрезанный на несколько страниц, чужой поток в том же файле,
порченые и обрезанные файлы, MP3/M4A/Vorbis вместо Opus, таблица клиентов и
запасные совпадения, экранирование HTML из файла. Разбор MP4: бренды, кодеки,
имя кодировщика и `©too` из настоящего файла ffmpeg (сверено с exiftool) и из
собранных вручную, `meta` в стиле QuickTime, битые и обрезанные файлы. Плюс
прогон настоящих апдейтов через диспетчер: голосовое, кружок и видео, `.ogg` и
`.mp4` документом, PDF и MP3 без скачивания, файл больше 20 МБ, упавшая сеть,
молчание в группах. И разбор ввода установщика: вставка с невидимым мусором,
токен вперемешку с текстом.

## Структура

```
voicebot/
  __main__.py   запуск бота
  handlers.py   приём голосовых и кружков, ответы
  opus.py       разбор Ogg/Opus: достаёт строку Vendor
  clients.py    таблица Vendor → клиент
  mp4.py        разбор MP4: что внутри кружка/видео
tests/          проверки без сети
install.sh      установка одной командой
```
